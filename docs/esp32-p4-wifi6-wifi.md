# Waveshare ESP32-P4-WIFI6: Wi-Fi via ESP32-C6

The ESP32-P4 has no native radio. On this board, an ESP32-C6 coprocessor provides Wi-Fi and Bluetooth through the ESP-Hosted SDIO link.

## PlatformIO environment

Use `[env:esp32-p4-wifi6]` in the root `platformio.ini`. This environment differs from the audio-only P4-Pico profile:

- It uses `framework = arduino, espidf`, so the Arduino core is built as an ESP-IDF component.
- It is pinned to pioarduino `55.03.312-1` (Arduino-ESP32 3.3.12 / ESP-IDF 5.5.5) as a compatibility baseline for the hosted components.
- The ESP32-P4 target pulls `espressif/esp_hosted` and `espressif/esp_wifi_remote` from the Arduino core's ESP-IDF component manifest.
- `board_build.cmake_extra_args` selects the tracked `sdkconfig.defaults.esp32-p4-wifi6` through `SDKCONFIG_DEFAULTS`. This is needed because pioarduino ignores `custom_sdkconfig` in the combined `arduino, espidf` mode. The defaults select the ESP32-C6 coprocessor, a 1 kHz FreeRTOS tick rate and the P4 Function-EV-compatible SDIO pin preset.

The SDIO signals are CLK=GPIO18, CMD=GPIO19, D0-D3=GPIO14-17, with C6 reset on GPIO54. These pins are reserved while Hosted Wi-Fi is enabled; do not reuse them for other peripherals. The onboard microSD interface uses different pins.

The first build needs access to the ESP Component Registry so the required components can be resolved.

## Verify Wi-Fi connectivity

Copy `examples/HardwareTesting/P4WifiStation/P4WifiStation.cpp` to your local PlatformIO project's `src/main.cpp`. Create `src/secrets.h` locally with your network details:

```cpp
#define WIFI_SSID "your-2.4-GHz-SSID"
#define WIFI_PASS "your-password"
```

Do not commit real Wi-Fi credentials. The ESP32-C6 on this board uses 2.4 GHz Wi-Fi; a 5 GHz-only SSID will not work.

If changing the SDK defaults after the first build, rename or remove the generated `sdkconfig.esp32-p4-wifi6` first; otherwise ESP-IDF will reuse its previous values. Keep a backup if you have customized it.

Build, upload and open the monitor:

```sh
pio run -e esp32-p4-wifi6 -t clean
pio run -e esp32-p4-wifi6
pio run -e esp32-p4-wifi6 -t upload
pio device monitor -e esp32-p4-wifi6
```

The example reports the connection status, DHCP address and RSSI. The existing Beatsy Internet Radio example uses the standard Arduino `WiFi` API, so it can use the same environment after credentials are configured.

## C6 coprocessor firmware version mismatch

The Arduino-ESP32 3.3.12 core includes `ESP_HostedOTA`, which can update the ESP-Hosted firmware on the C6 over the working Wi-Fi connection. This is separate from uploading the application to the P4.

1. Copy `examples/HardwareTesting/P4WifiHostedOTA/P4WifiHostedOTA.cpp` to the local project's `src/main.cpp`. Keep the local `src/secrets.h` with your Wi-Fi credentials.
2. Build and upload the updater to the P4:
   ```sh
   pio run -e esp32-p4-wifi6 -t clean
   pio run -e esp32-p4-wifi6
   pio run -e esp32-p4-wifi6 -t upload
   pio device monitor -e esp32-p4-wifi6
   ```
3. Keep the board powered while the updater downloads the official ESP32-C6 v2.13.0 image, transfers it to the C6 over ESP-Hosted, and restarts the P4 after reported success. The version in the URL is generated by the installed Arduino core.
4. After reboot, inspect the log. The expected result is that the host can read the C6 version and no longer reports `Co-proc [0.0.0]` or a version mismatch.

**Security note:** The upstream `ESP_HostedOTA` implementation in Arduino-ESP32 3.3.12 uses HTTPS but disables certificate verification. It fetches the fixed Espressif URL; only run it where you trust the network, and do not adapt it to arbitrary firmware URLs.

If OTA fails (for example, `hostedBeginUpdate` or `hostedWriteUpdate` fails), do not keep retrying blindly. Record the complete log first. The fallback is manual C6 UART flashing using Waveshare's instructions: connect a 3.3 V TTL adapter to the C6 UART pads, hold C6 IO9 low before power-on, and hold the board BOOT button so the P4 does not control the C6 reset. Use only a verified firmware image for the P4 host's ESP-Hosted version. Do not flash the P4 application image to the C6.

The Wi-Fi station test has been verified on the physical board based on the reported serial log. The OTA updater itself has not yet been run on the physical board.
